## Findings (each proven by a test that exits 1 on head)

### Medium

1. **`tests/review1_identifier_trailing_newline.py`** (3 failed, 1 passed)
   - `_EVENT_TYPE` and `_ACTOR` are `^...$` patterns (src/argus_ledger/canonical.py:37, :40), applied with `re.match` (canonical.py:67, :73). In Python `$` also matches before a final `\n`, so `"tool.exec\n"` and `"agent\n"` pass.
   - `append()` stores them, and both verifiers accept the record because neither checks identifiers on read.
   - The Rust `validate_identifiers` checks every byte (src/lib.rs:580-593) and refuses them. This is a Python/Rust writer-parity gap, the kind §2.A says must not exist. It also breaks the log-injection rule that the grammar's own comment (canonical.py:38-39, :63-65) exists to enforce.
   - timestamps.py:22-23 already documents this exact `$` pitfall and uses `fullmatch`. The identifier gate does not.
   - Fix: `fullmatch` (or `\Z`).

2. **`tests/review1_torn_tail_long_name_bricks.py`** (1 failed, 1 passed)
   - The sidecar name is `f"{ledger_path}.torn-{offset}-{stamp}"` (ledger.py:555), about 30-35 bytes longer than the ledger's own file name.
   - For any ledger file name longer than about 220 bytes (still valid, NAME_MAX = 255), `os.open(sidecar)` fails with ENAMETOOLONG and `_set_aside_torn_tail` raises `LedgerCorruptionError` (ledger.py:566-570). It removes nothing, so the next append fails the same way, and every one after it.
   - This reopens the "torn tail blocks every append" problem (R3-9 in docs/SECURITY_ASSESSMENT_SCOPE.md §3) for a whole class of paths. A short name recovers (control).
   - Fix: a bounded sidecar name, e.g. truncate or hash the base name.

3. **`tests/review1_append_truncates_foreign_file.py`** (1 failed, 1 passed)
   - If the ledger path holds an ordinary one-line file with no final newline (a config value, a token, a note), append treats the whole file as a torn record: the bytes after the last newline do not parse (ledger.py:456-458), and with no record before them the tail is `None` (ledger.py:461).
   - `_set_aside_torn_tail` then truncates the file to 0 and writes a genesis record (ledger.py:486-488). The original bytes survive only in a `.torn-0-*` sidecar.
   - A newline-terminated foreign file is correctly refused (control). So whether a file is destroyed or refused depends on one trailing byte.
   - A fragment this package leaves behind always starts with `{` (each write starts with a record, or with `\n{`). A fragment that does not, or one that is the whole file, was never a record and should be refused, not removed.

4. **`tests/review1_ctor_chmods_symlink_target.py`** (1 failed, 1 passed)
   - `__init__` runs `os.stat`/`os.chmod` on the path (ledger.py:377-379). Both follow symlinks, so constructing any `AppendOnlyLedger` on a symlink strips group/other bits from the target, wherever it lives. That includes a read-only `verify_key` ledger, which cannot append.
   - The README says opening a ledger "creates nothing", and verification is supposed to be passive. In a ledger directory others can write, a verifier (an auditor, a root cron job) can be made to chmod any file it owns.
   - `append()` follows the symlink the same way: it fchmods and appends to the target, `_open_locked_for_append` ledger.py:392-433.
   - Fix: `os.lstat` plus `O_NOFOLLOW`, or refuse non-regular files.

5. **`tests/review1_load_key_strips_binary_key.py`** (1 failed, 1 passed)
   - `load_key()` returns `fh.read().strip()` (ledger.py:390). Ed25519 seeds and HMAC keys are raw bytes, and about 1 in 21 random 32-byte seeds starts or ends with a byte in `b" \t\n\r\x0b\x0c"`.
   - Such a seed loads shorter and different: an Ed25519 ledger then refuses to open (len != 32), and an HMAC key silently differs from the file that other tools read.

6. **`tests/review1_praxa_missing_action_authorized.py`** (4 failed, 1 passed)
   - `evaluate_proposal()` reads `value.get("action", "")` (proofweave.py:453-454). An intent with no `action` member, with `Action`, with only `tool`, or with `action: ""` gets the name `""`. That passes the deny-list, and the intent is AUTHORIZED with a live token.
   - The docstring (proofweave.py:441) says an intent whose action is not a string is REJECTED. A missing action is not a string action.
   - This governor's only policy check is the deny-list, so `{"tool": "drop_database"}` is authorized under a policy that prohibits `drop_database`.

### Low

7. **`tests/review1_bytes_path_torn_tail.py`** (1 failed, 1 passed): `os.path.abspath(bytes)` keeps the path as bytes (ledger.py:371), and the f-string at ledger.py:555 then gives the sidecar path `"b'/.../audit.jsonl'.torn-…"`, which is relative and nonexistent. Torn-tail recovery therefore always fails for a bytes path, and the ledger blocks. Either refuse bytes paths in `__init__` or use `os.fsdecode`.

8. **`tests/review1_verify_directory_raises.py`** (4 failed, 1 passed)
   - `verify_chain()` checks only `os.path.exists` (ledger.py:774), which is true for a directory. `_snapshot_lines` opens the directory and reads `st_size` bytes from it (ledger.py:180-191).
   - An empty directory (st_size 0 on this filesystem) verifies as a valid empty ledger. A non-empty one raises `IsADirectoryError`. A missing file is `valid=False`.
   - Native and pure-Python paths behave the same. `AppendOnlyLedger("")` resolves to the working directory and hits the same bug. `head()` raises too (ledger.py:590).

9. **`tests/review1_str_key_verify_raises.py`** (3 failed, 1 passed)
   - `__init__` checks only `len()` of `signing_key`/`verify_key` (ledger.py:357, :362), so a key read in text mode is accepted.
   - `verify_chain()` then raises `TypeError`: from `hmac.new` (hasher.py:120) on the HMAC path, and from pyo3 or `bytes(str)` (hasher.py:155) on the Ed25519 path. It never returns a report.
   - `verify_signature()` catches only `ValueError` (hasher.py:188-191), so it raises for a str key instead of returning a bool.

10. **`tests/review1_int_key_payload_writer_split.py`** (1 failed, 1 passed): `validate_payload()` deliberately keeps integer keys whose order survives storage (canonical.py:82-99). `append()` then builds `AuditEvent(payload=...)` (ledger.py:515), whose `Dict[str, Any]` (models.py:22) rejects them with a pydantic `ValidationError`, not a `PayloadError`. The public validator and the writer disagree. Nothing is written, so this fails closed.

11. **`tests/review1_event_id_unchecked.py`** (2 failed, 1 passed): the only handling of `event_id` is `eid = event_id or str(uuid.uuid4())` (ledger.py:444). Control characters and ANSI escapes (refused in `actor`) are stored, and so is any length: a 4 MiB event_id gives a 4 MiB record although payloads are capped at 1 MiB (canonical.py:29, :142). The Rust writer never takes a caller event_id (src/lib.rs:1193).

12. **`tests/review1_ledger_dirs_not_owner_only.py`** (1 failed, 1 passed): `_make_directories` calls `os.makedirs(directory, exist_ok=True)` with the default mode (ledger.py:96), which gives 0755 under umask 022. The `__init__` docstring (ledger.py:349) says "the file and its missing directories are created owner-only". The file is 0600 (control). The directory listing, with ledger and sidecar names, sizes and mtimes, is world-readable.

13. **`tests/review1_proofweave_seal_coercion.py`** (4 failed, 1 passed): `ProofWeaveTransaction.create` and `AgentTraceBinding.create` format the caller's raw `step_index`/`timestamp_epoch_ms` into the seal (proofweave.py:283, :132), but the models store pydantic's coerced int (proofweave.py:258, :263, :111). So for `3.0` or `True`, `verify()` with exactly the sealed inputs returns False.

14. **`tests/review1_policy_binding_int_keys.py`** (1 failed, 1 passed): `PolicyActionBinding.create` hashes `canonical_json_bytes(intent)` with no `validate_payload` (proofweave.py:56-58). For `{2: .., 10: ..}`, `json.dumps` sorts the keys as ints. Once the intent is stored and reloaded as JSON, the keys sort as strings and `verify()` returns False for the same intent. This is the problem `_check_keys` solves for the ledger (canonical.py:85-89).

15. **`tests/review1_blinded_commitment_salt.py`** (2 failed, 1 passed): `create_blinded_commitment` accepts any salt, including `b""`, and any payload type, and hashes `canonical || salt` with no length framing (proofweave.py:599-603). `salt=b""` is a bare SHA-256 of the payload, so it does not hide it. `(1, b"2")` and `(12, b"")` give one commitment, so it does not bind either.

16. **`tests/review1_rag_seal_omits_mean.py`** (2 failed, 1 passed): the `evaluation_seal` preimage (proofweave.py:216) leaves out `triad_harmonic_mean` and rounds the three scores to 4 decimals, although the field docstring says "seal of the full evaluation tuple" (proofweave.py:193). Means of 0.10 and 0.95 give the same seal. The module is marked experimental.

## Checked, holding (no finding)

- `timestamp_nanos` uses `fullmatch`, `[0-9]` and digit/u64 caps (timestamps.py:22-41).
- `_parse_record` refuses unknown or duplicate members, non-int sequence and hash_version, `-0`, over-deep nesting before `json.loads`, unpaired surrogates, raw CR/LF, and non-UTF-8 (ledger.py:249-297).
- `validate_payload` handles floats, |int| > 2^53-1, depth 112 (self-reference included), the 1 MiB canonical size, and non-string keys whose order changes (canonical.py:82-143). Lone surrogates in a payload are refused before anything is written (`UnicodeEncodeError` from canonical.py:152; it is not a `PayloadError`, a cosmetic point).
- `verify_chain(legacy_timestamps_before=...)` refuses bool, non-int and values < 1 (ledger.py:762-768). Anchors past u64 are mapped on the native path.
- `verify_signature` takes the scheme from the verifier, never from the signature. Ed25519 accepts only lowercase hex and refuses small-order keys and R points (hasher.py:143-192). A 64-char hex `verify_key` is refused by length.
- A NUL byte in `ledger_path` raises `ValueError` in `__init__` (os.stat). A ledger file is created with `O_EXCL` and 0600, and the sidecar with `O_EXCL` (so not through a planted symlink).

## Suspected, unconfirmed (not provable in-process without stalls, another uid, root, or races)

- `load_key()` on a FIFO (or `/dev/stdin`) blocks forever: no `S_ISREG` check (ledger.py:384-390). Not tested, because the brief forbids stalls.
- `load_key()` checks only mode bits, not ownership. Run as root, it accepts a 0600 key file that another user owns and can rewrite. It also stats and opens separately (TOCTOU), so the mode check can be raced. Confirming either needs a second uid or a race.
- Run as root, `AppendOnlyLedger(link_to_/dev/null)` would chmod `/dev/null` to 0600 (finding 4), and `append()` would `fchmod` it (ledger.py:128-142). Not run, because it is destructive and this user is not root. `verify_chain()` on a path pointing to `/dev/null` reports a valid empty ledger (st_size 0), like the empty-directory case in finding 8. That is consistent with "an empty chain passes" without an anchor.
- Praxa deny-list matching is exact and case-sensitive: `{"action": "DROP_DATABASE"}` and `"drop_database "` are authorized while `"drop_database"` is prohibited (proofweave.py:454). Whether this is exploitable depends on how the broker normalises names. It is recorded here as a design note, not filed.
- `get_event(True)` returns sequence 1 (`1 == True`), `get_event("1")` returns None, and `iter_events(start="1")` raises `TypeError` mid-iteration (ledger.py:625-629, :717-723). There is no type validation, but the impact is negligible, so not filed.
